# 04 券级响应模型：谁会完成这张券

> 输入：`data/clean/transcript.csv`、`portfolio.csv`、`profile.csv`、`user_segments.csv`
> 输出：`04_offer_dataset.csv`、`04_metrics.csv`、`04_feature_importance.csv`、`04_segment_eval.csv`、`04_calibration.csv`、`04_lift.csv`、`04_lgbm_model.txt`、5 张图
> 一句话结论：**模型能把"会用券的人"排出来（AUC 0.866，PR-AUC 0.876），但最重要的特征是历史客单价——它预测的是"会不会用"，不是"券是否带来增量"。所以模型只能做分层内的排序器，不能替代 03 的人群规则，更不能替代 05 的 uplift。**

---

## 1. 样本怎么构造

一行 = **一次发券**（offer received），共 76,277 行；标签 = 这次发券后是否发生对应的 offer completed。

关键处理：

1. **同一用户会多次收到同一张券**（11,718 组、24,707 次），完成事件也可能多次（4,583 条重复）。做法是把每个完成事件回溯到"最近一次、且仍在有效期内的发券"，避免把一次完成重复记到多次发券上。
2. 最终 **33,101 个发券实例为正样本**（占全部发券 43.4%）；33,579 个完成事件全部匹配成功，没有无主完成。
3. **信息型券（15,235 次，占 20%）不参与训练**：它天然不可能完成，放进去会让模型学到一个"白送"的强特征，把 AUC 虚高到 0.91。信息型券在打分时按规则 `p=0`。
4. 建模样本 = 61,042 条可完成券（BOGO + 折扣），正样本率 **54.2%**。

## 2. 防泄漏设计（本脚本最重要的部分）

| 风险 | 处理 |
|---|---|
| 用 01 的全窗口 `comp_rate`、`monetary` 等特征 | **不用**。这些统计包含当前这张券的结果，属于目标泄漏 |
| 用 02 的人群标签当特征 | **不用**。人群标签由全窗口行为聚类得到，预测新用户时不可得；只用于分人群评估 |
| 历史特征包含发券之后的事件 | 所有历史特征严格取 `time < send_time` 的事件；同一时刻的交易也不计入 |
| 同一用户同时进训练集和测试集 | `GroupShuffleSplit` 按 `person` 切分：训练 13,542 人 / 测试 3,386 人 |
| 用测试集早停 | 训练集内部再按用户切 15% 做验证集，早停后再用全训练集重训 |

最终特征 46 个，分五组：

- **静态画像**：年龄、收入、性别、人口属性缺失、会员天数；
- **历史交易**：历史笔数/消费额/客单价/最大单笔/活跃天数、距上次交易小时、近 7 天笔数/消费额；
- **历史券行为**：历史收券/查看/完成、查看率、可完成券完成率、BOGO/折扣分别的收券与完成、折扣偏好、信息型收券与查看、券种数；
- **当前券**：BOGO/折扣、门槛、补贴、单次净额、有效期、补贴/门槛、门槛/客单价、门槛−客单价；
- **发送上下文**：发送时段、活动第几天、第几次收券。

## 3. 模型与整体指标

LightGBM 二分类，`learning_rate=0.05`、`num_leaves=31`、`min_data_in_leaf=80`、`feature_fraction=0.8`、`bagging_fraction=0.8`、`lambda_l2=1.0`，早停 80 轮，最佳迭代 257。

| 指标 | 值 | 说明 |
|---|---|---|
| 测试样本 | 12,192 条 | 3,386 个未见用户 |
| 正样本率 | 54.2% | 可完成券口径 |
| **AUC** | **0.866** | 排序能力 |
| **PR-AUC** | **0.876** | 基准（随机）0.545 |
| Brier | 0.147 | 概率校准误差 |
| LogLoss | 0.455 | — |
| 最佳 F1 | 0.815 | 阈值 0.419 |
| Top 10% 提升 | 1.76 倍 | 前 10% 捕获 17.6% 的完成 |

### 3.1 特征 ablation：用户历史到底值多少

同一切分下的快速对照（简化参数，仅看方向）：

| 特征集 | AUC | PR-AUC |
|---|---|---|
| 只用券属性（类型/门槛/补贴/有效期） | 0.591 | 0.616 |
| 券属性 + 核心用户历史（交易/客单/收券/完成率/会员天数） | 0.838 | 0.852 |
| 全量 46 特征 | **0.866** | **0.876** |

结论：**券本身只解释一小部分，真正决定完成的是"这个人是谁"**。这也是后面所有局限的根源。

### 3.2 分券种与分人群的判别力

| 子集 | n | AUC | PR-AUC |
|---|---|---|---|
| BOGO 券 | 6,065 | 0.863 | 0.854 |
| 折扣券 | 6,127 | 0.868 | 0.891 |
| 两个选择性人群 | 5,429 | 0.708 | 0.707 |

全样本 AUC 0.866，但一进入真正的决策池（选择性人群），AUC 降到 0.708——**人群内部同质化后，模型更难区分**。这比报一个 0.86 更诚实，也说明模型适合"粗排 + 人工规则"，不适合单独做精细定价。

## 4. 分人群校准：模型在哪里失灵

| 人群 | n | 实际完成率 | 模型预测 | 组内 AUC |
|---|---|---|---|---|
| 高价值·全响应 | 3,402 | 98.9% | 82.8% | 0.502 |
| 高价值·选择性 | 2,923 | 58.2% | 59.1% | **0.736** |
| 中价值·选择性 | 2,506 | 45.5% | 47.7% | **0.649** |
| 中价值·零完成 | 1,996 | 0.0% | 20.6% | — |
| 中价值·全响应 | 395 | 98.2% | 70.7% | 0.644 |
| 低价值·低活跃 | 373 | 0.0% | 27.7% | — |
| 高价值·零完成 | 296 | 0.0% | 29.7% | — |
| 中价值·低活跃 | 290 | 19.0% | 32.7% | 0.573 |
| 低价值·零完成 | 11 | 0.0% | 15.5% | — |

三件事必须讲清楚：

1. **全响应人群组内 AUC 只有 0.502**：不是模型坏了，而是这个人群的可完成券完成率 99%，几乎没有“排序”空间。对这群人，规则（停发）比模型更有用。
2. **零完成人群被明显高估**：实际 0%，模型给 15%–30%。因为模型只能看到发券前的交易/画像，看不到“这张券的门槛高于他的客单”这一结构性事实；他们的历史特征和低价值用户太像。**所以不能用模型分数直接决定发不发，必须先用 02 的人群规则兜底。**
3. **全局校准很好，分人群校准很差**：整体预测 vs 实际几乎落在对角线上（10 个分箱最大偏差约 2pp），但组内偏差可达 30pp。这是典型的“辛普森式”校准问题——平均准，不等于每个人群都准。

## 5. SHAP：什么在驱动完成

| 特征 | 增益占比 | 平均 \|SHAP\| | 方向 |
|---|---|---|---|
| 历史客单价 | 33.1% | 0.614 | 客单价越高，越可能完成 |
| 会员天数 | 12.8% | 0.589 | 老会员更可能完成 |
| 历史最大单笔 | 7.8% | 0.093 | 正向，但边际小 |
| 收入 | 7.8% | 0.271 | 高收入更可能完成 |
| 年龄 | 5.9% | 0.188 | 中年段更高 |
| 补贴 | 5.4% | 0.324 | **高补贴反而常为负贡献**（与高门槛绑定） |
| 门槛/客单价 | 3.5% | 0.230 | 比值越高，越难完成 |
| 门槛−客单价 | 3.0% | 0.152 | 差值越大，越难完成 |
| 门槛 | 2.9% | 0.176 | 高门槛负向 |
| 历史消费额 | 1.9% | 0.115 | 正向 |

读法：

- **模型首先学的是"客户价值"，不是"券的吸引力"**。历史客单价 + 会员天数 + 历史最大单笔 + 收入 + 年龄合计贡献约 67%。这解释了为什么全响应人群预测高：他们本来就是高价值老客。
- **补贴不是越高越好**。SHAP 上高 `reward` 的点多在负侧，因为高 reward 的券（10-2、20-5）同时伴随高 difficulty；单看面额会误判，必须和门槛一起看。
- **门槛/客单价是有效的“可达性”特征**。它排进前 7，说明“这张券对这个人的客单来说是否够得着”确实影响完成。
- **发送时段/日期几乎没有贡献**：与 02 的结论一致，这份数据没有时段偏好信号，不要硬做“最佳发送时间”。

## 6. 业务结论：模型怎么用

**05 后：规则决定“发不发”，模型只在“决定发券”的人群内做排序/诊断。**

> **05 修正（2026-11-25）：** 03 的旧规则“全响应停发、只对选择性开放”已被 05 的增量评估推翻。05 显示全响应人群券相对信息型仍有 +9.6/+20.5pp 的购买率增量，而选择性人群的增量 GMV 不足以覆盖补贴。以 `05_增量评估.md` 的 v2 为准：只给两个全响应人群发折扣 7-3，其余发信息型；但 v2 是回溯上限测算，人群标签发券时不可得，不是可上线规则。04 的模型仍然正确，但它的定位是“**在已经决定发券的人群里排序/诊断**”，不是“决定谁该发券”。

**05 后的规则（以此为准）：**

1. **只给两个全响应人群发折扣 7-3**：高·全响应、中·全响应。这两群的可完成券完成率接近 100%，04 模型组内 AUC 只有 0.502，没有排序空间；正确动作是“统一发 d7”，不是“用模型挑人”。
2. **选择性、零完成、低活跃只发信息型**：05 显示选择性人群的 d7 购买率增量为正，但增量 GMV 覆盖不了 3 元补贴；零完成/低活跃为负。04 模型不用于给这批人发券。
3. **04 模型保留两个用途**：
   - 如果未来对选择性人群做小流量券测试，用它在测试组内排序：测试集选择性人群整体完成率 52.3%，前 10% 80.1%、前 20% 75.1%，前 20% 捕获 28.7% 的完成；
   - 作为诊断工具，解释“完成概率高 ≠ 增量高”，防止再犯“AUC 0.866 所以券有效”的错误。
4. 模型分数可以用于“频控”：在决定发信息型的人群里，低分用户降低发送频次，高分用户保持触达优先级。

**03 旧规则（保留作对照，已被 05 推翻）：** 全响应停发、只对两个选择性人群发折扣 10-2。05 用信息型券作准对照重算后，S1 的增量净额约 −3.08 万；v2 约 +11.96 万（回溯上限测算，不是可上线规则）。

**错误用法：**

- 用模型分数直接替代人群规则——会在零完成人群上浪费 15%–30% 的预算；
- 把高 AUC 当成"券有效"的证据——模型预测的是 completion，不是 increment；
- 用 04 模型给全响应人群排序——组内 AUC 0.502，没有排序信息；但“不能排序”不等于“不能发券”：05 显示全响应人群发 d7 仍有 +12.9/+20.6pp 的购买率增量，正确动作是统一发 d7，而不是用模型挑人。

## 7. 局限

1. **观测数据，没有随机对照**：模型学的是"收到券且完成"的条件概率，不是"因为券才完成"的因果效应。05 用信息型券做准对照、用户 FE 估计增量，比 04 更接近因果，但仍依赖“券 vs 信息型准随机”的假设。
2. **券的分配不是随机的**：不同人群收到的券型、时机、频次不同，模型会继承投放策略的选择偏差。
3. **冷启动**：新用户没有历史交易/收券，模型只能靠年龄、收入、会员天数，预测会向均值收缩。
4. **分人群校准失败**：零完成人群被高估 15%–30%，必须靠规则兜底；如果未来要单独给这群人打分，需要加入"门槛/客单"的硬规则或分层校准。
5. **completion ≠ GMV / 增量**：模型预测完成概率，不预测完成后的客单/净额，也不预测“因为券才多买”；预算优化要看 05 的增量净额，不是 04 的 p_complete。

## 8. 下一步：05 增量/uplift（已完成）

> 05 已按“信息型券作准对照 + 用户固定效应”跑完，结论见 `05_增量评估.md`。本节保留当时的计划，作为方法演进记录。

04 已经证明"响应模型只能排序，不能证明增量"。05 要回答的是：

- 同一人群，发券 vs 不发券的完成率差多少？
- 哪些人是"因为券才买"（persuadable），哪些是"本来就会买"（sure thing），哪些是"发券也不买"（lost cause）？

这份数据没有真正的对照组，05 会用两种退而求其次的方案，并在文档中明确标注假设：

1. **双模型差分**：用"发券样本"训练响应模型，用"无券/信息型样本"训练基线购买模型，分数差作为增量代理；
2. **券型自然实验**：同一人群在不同时段收到不同券型，比较完成率差异，控制人群/时间后估计相对增量。
