# 简历项目描述：优惠券精准投放与增量效果评估

**项目类型**：个人项目 / 公开数据策略分析（Starbucks Promotions）  
**建议岗位**：数据分析、商业分析、增长策略、业务型数据科学、数据挖掘  
**技术栈**：Python、Pandas、Scikit-learn、LightGBM、SHAP、DuckDB、Spark SQL（兼容写法）、HTML/ECharts、unittest

---

## 直接可粘贴版（3 条）

- 基于 17,000 用户 / 306,534 条事件搭建优惠券投放分析链路，构建 RFM + 行为双聚类（3×4 → 9 人群）与 9 人群×6 券型策略矩阵；识别“完成率≠增量净额”，将发券收缩到高/中价值全响应 d7，期望核销补贴由 16.5 万降至 7.2 万（−56.1%），增量净额 11.96 万、ROI 2.66（回溯上限测算，非可上线规则）。
- 用 LightGBM 建响应排序模型（测试集 AUC 0.866 / PR-AUC 0.876，top 10% lift 1.76），并以信息型券为准对照、用户固定效应 + T-learner 评估增量（72h 购买率 +2.36pp、GMV +1.48 元/次）；设计 5,542 人分层 A/B，合并净 GMV MDE 3.19 元、power 99.5%，量化 2.5 元 MDE 缺口 3,488 人。
- 用 Spark SQL 兼容写法完成 9 条查询，DuckDB 本地执行、34 项对账全过；补 PSI、模型衰减、券效与数据量监控，识别行为历史特征 PSI 高为回看窗口伪影（分数 PSI 0.06、监控 AUC 0.864→0.879）；`run_all` 一键复现 10 步（约 5 分钟）+ 9 项回归测试。

## 面试展开顺序（每题 30 秒）

1. **为什么做这个项目**：公开数据能还原“分层—发券—增量—预算”完整链路，且能纠正“完成率高就是好券”的常见误区。
2. **最大发现**：高价值·全响应 4,832 人完成 51% 的券、消耗 53% 的补贴；但他们本来就会买，S1 账面 +16.8 万，同口径只有 −3.08 万。
3. **怎么证明增量**：信息型券同触达、无购买激励，做准对照；用户固定效应吸收稳定画像；72h 购买率 +2.36pp，不是完成率看到的 100%。
4. **策略怎么落**：只给高/中价值全响应发 d7，其余信息型；期望核销补贴 7.2 万，增量净额 11.96 万，ROI 2.66。但这是回溯上限测算，人群标签发券时不可得，不能直接上线。
5. **怎么保证不翻车**：A/B 功效计算（5,542 人、MDE 3.19、power 99.5%）；SQL 34 项对账；PSI/模型衰减/券效监控；run_all + 回归测试。
6. **边界**：准实验不是 RCT；预算是点估计；A/B 是方案；监控是离线回放；Spark SQL 只做兼容写法、本地 DuckDB 验证；v2 的下一步是小流量 A/B，当前没有线上实验。

## 不要写进简历的说法

- “线上 A/B 提升 ROI 2.66” → 实际是回溯预算模拟 + A/B 方案。
- “Spark 集群落地” → 实际是 Spark SQL 兼容写法 + DuckDB 本地验证。
- “因果证明券有效” → 实际是观测数据准实验。
- “模型准确率 100%” → 完成率是描述指标，不是增量。
