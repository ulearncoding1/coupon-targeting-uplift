# user_features.csv 特征字典

17,000 行 × 52 列，一个用户一行。由 `01_profile_rfm.py` 从 `transcript.csv` / `profile.csv` / `portfolio.csv` 构建。

## A. 价值维度（RFM）— 回答「给谁发」

| 字段 | 含义 | 口径 |
|---|---|---|
| `recency_h` | 距最近一次消费多少小时 | 720 − 最后交易时间 |
| `n_tx` | 交易笔数 | 事件计数 |
| `monetary` | 消费总额 | amount 求和 |
| `avg_order_value` | 客单价 | monetary / n_tx |
| `max_order_value` | 最大单笔消费 | amount 最大值 |
| `n_active_days` | 有消费的天数 | 去重 day |
| `tx_per_active_day` | 活跃日日均单量 | n_tx / n_active_days |
| `active_day_ratio` | 30 天活跃占比 | n_active_days / 30 |
| `first_tx_h` / `last_tx_h` | 首次 / 末次消费时间 | 距实验开始的小时数 |

## B. 探索维度 — 回答「给谁发」的第二条轴

| 字段 | 含义 | 口径 |
|---|---|---|
| `hour_entropy` | 消费时段分散度（bit） | 24 小时分布香农熵，越大作息越不固定 |
| `day_entropy` | 消费日期分散度（bit） | 30 天分布香农熵 |
| `night_share` | 夜间消费占比 | 0–6 点交易占比 |
| `channel_breadth` | 收到券覆盖渠道数 | 1–3；97% 用户为 3，判别力弱，**不建议进聚类** |
| `n_offer_types_recv` | 收到券型种类数 | 1–3（BOGO / 折扣 / 信息型） |

## C. 触达响应 — 回答「发完是否有效」

| 字段 | 含义 | 口径 |
|---|---|---|
| `n_offer_recv` / `n_offer_view` / `n_offer_comp` | 收 / 看 / 用事件数 | 含重复触达 |
| `view_rate` | 收→看率 | view / recv（含信息型券，衡量注意力） |
| `comp_rate` | 收→用率 | **只算可完成券（BOGO+折扣）**，信息型券不进分母 |
| `view_to_comp_rate` | 看→用率 | comp / 可完成券的查看次数 |
| `unviewed_rate` | 未查看率（触达不足） | 1 − view_rate |
| `viewed_not_comp_rate` | 看了没买（说服失败） | 1 − view_to_comp_rate |
| `info_share` | 信息型券在触达里的占比 | recv_info / 总触达，用于识别"纯广告稀释" |

## D. 券型偏好 — 回答「给谁发什么券」

| 字段 | 含义 |
|---|---|
| `recv_bogo` / `comp_bogo` / `comp_rate_bogo` | 买赠券：收到 / 完成 / 完成率 |
| `recv_discount` / `comp_discount` / `comp_rate_discount` | 折扣券：收到 / 完成 / 完成率 |
| `recv_info` / `view_info` / `view_rate_info` | 信息型券：收到 / 查看 / 查看率（无完成概念） |
| `pref_discount` | 折扣偏好强度 = 折扣完成率 − 买赠完成率，>0 更吃折扣，<0 更吃买赠 |

## E. 门槛耐受与补贴 — 回答「发多大力度的券」

| 字段 | 含义 | 口径 |
|---|---|---|
| `recv_hard` / `comp_hard` / `comp_rate_hard` | 高门槛券（difficulty ≥ 10） |
| `recv_easy` / `comp_easy` / `comp_rate_easy` | 低门槛券（difficulty 5 / 7） |
| `hard_minus_easy` | 门槛耐受度差 = 高门槛完成率 − 低门槛完成率 |
| `avg_offer_ratio` | 收到券的平均让利强度 = reward / difficulty |
| `total_reward_earned` | 已核销补贴总额（完成券拿到的 reward 之和） |

## F. 人口属性

| 字段 | 含义 |
|---|---|
| `age` / `income` | 年龄 / 收入，缺失 12.8%（原值 age=118 为缺失标记） |
| `gender` | M / F / O / Unknown |
| `tenure_days` | 相对会员时长（最晚注册日 − 本人注册日） |
| `demo_missing` | 人口属性缺失标记 |

## 标签

| 字段 | 占比 |
|---|---|
| `y_tx_any` 有过消费 | 97.5% |
| `y_view_any` 看过券 | 99.0% |
| `y_comp_any` 完成过券 | 75.1% |

## 缺失与边界（写代码/讲项目都要提前说清楚）

- **422 人（2.5%）无任何交易**：价值类特征为 NaN，`n_tx`/`monetary` 记为 0，用 `y_tx_any` 区分。
- **6 人无任何券事件**：券类「率」特征为 NaN（不是 0），计数为 0——「没被触达」和「触达后没反应」不能混。
- **2,175 人（12.8%）无人口属性**：保留 NaN + `demo_missing` 标记，聚类时统一处理。
- 同一用户同一张券常重复触达（86.5% 的用户×券组合出现多次），所有计数都按事件算。

## 后续用法建议

- **进聚类**：`recency_h, n_tx, monetary, avg_order_value, active_day_ratio, hour_entropy, day_entropy, comp_rate, view_rate, comp_rate_bogo, comp_rate_discount, pref_discount, hard_minus_easy, avg_offer_ratio, age, income, tenure_days`
- **不要进模型**：所有原始计数列（与率共线）、`y_*`（标签泄漏）、`channel_breadth`（97% 恒为 3）、`demo_missing`（仅作辅助分层）
- **NaN 处理**：连续特征中位数插补 + 缺失指示列，或 KNN 插补；6 个无券用户单列标记
