# 06 数据看板说明

## 一、怎么打开

直接双击：

```text
C:\Users\kk159\Desktop\优惠券投放复现\优惠券投放复现\outputs\看板\06_dashboard.html
```

不需要安装 Python、不需要联网、不需要启动 Streamlit。  
ECharts 图表库、主视图使用的数据与图片都已内嵌在这一个 HTML 文件里。  
图表可点击放大；04 的模型评估与特征解释用标签切换，避免把多面板图压小。  
七个页面各有主色（蓝 / 绿 / 赭 / 酒红 / 紫 / 青 / 棕），但共用暖纸底和宋体标题，图表保留原色。  
主视图不追求把 `figures` 目录里的每张中间图都贴一遍：能由数据直接画出的矩阵、热力图、预算图就在页面里交互生成，避免同一结论重复出现两三遍。

如果双击被浏览器拦截，可以把 `06_dashboard.html` 直接拖进 Chrome / Edge 窗口。

## 二、七个页面看什么

| 页面 | 回答的问题 | 关键内容 |
|---|---|---|
| 00 项目总览 | 这个项目到底解决什么问题 | 完成率≠增量、信息型券准对照、S1 账面 vs 增量、项目管线 |
| 01 人群分层 | 谁值得运营、谁值得发券 | 3×4 人群矩阵（人数/占比/完成率）、9+1 人群画像、行为簇画像 |
| 02 券型矩阵 | 同一人群发哪种券最划算 | 6 种券型的完成率、每千次净 GMV 热力图、03 现状审计 |
| 03 预算模拟 | 改补贴/触达量，增量净额怎么变 | 可调滑块、你的方案、S0/S1/v2 对比、v2 策略表 |
| 04 响应排序 | 模型能做什么、不能做什么 | AUC/PR/Brier/F1、ROC/PR/校准（标签切换）、累计提升、特征解释（Gain / 平均 \|SHAP\| / SHAP 分布）、分人群校准 |
| 05 增量评估 | 券相对纯提醒到底带来多少增量 | 分人群 CATE、分券型、人群×券型、T-learner 十分组、v2 策略 |
| 06 验证与落地 | 分析结论能不能被验收 | SQL 34 项对账、A/B 样本量与功效、监控回放、PSI 与告警 |

## 三、数据口径（答辩时不要说错）

- **03 的 S1 是历史方案**：只对两个“选择性响应型”人群发 d10，账面净额 +16.8 万。  
- **05 的 v2 是最终方案**：只对两个“全响应型”人群发 d7，其余发信息型；增量净额 +11.9 万。  
- **S1 在 05 的增量口径下是 −5.5 万**，因为“信息型券本来就会带来的购买”被 03 算成了券的功劳。  
- **04 的 `p_complete` 只做人群内排序**，不能单独回答“发不发券”。  
- 05 是“信息型券准对照 + 用户固定效应”，不是严格 RCT；答辩时用“准实验/准对照”，不要说“证明因果”。

## 四、怎么重新生成

如果改了 02–05 的分析结果或 07–09 的验证结果，在项目根目录运行：

```powershell
python src\06_build_dashboard.py
```

注意：06 的“验证与落地”页依赖 07–09 的产物；单独运行前要先有 `sql/_validation.csv`、`08_ab_power.csv` 和 `09_*.csv`。最稳的入口是：

```powershell
python src\run_all.py
```

它会按 02–05 → 07–09 → 06 的依赖顺序执行。

它会重新读取：


## 五、已知边界

1. 预算模拟是“点估计外推”，不含毛利、固定成本、履约成本；滑块调的是假设，不是重新跑模型。
2. 05 的分人群×券型有些格子样本较小（如低·零完成 n≈11），看板保留数字但不要过度解读。
3. T-learner 的 Top 20% 是整体 gap 的约 6 倍，但十分组不是完全单调（第 3 组有回落），不能当精确点估计。
4. 看板是静态数据，不会自动更新；数据更新后要重新运行 `src\06_build_dashboard.py`。
5. 06 验证页的 SQL、A/B、监控数据来自 07–09；只改验证层时，也要重新构建看板，否则页面仍是旧快照。

## 六、图片取舍（为什么不是全部原图都贴）

`outputs\figures` 里共有 16 张原始成图。主视图实际嵌入 10 张；其中 `04_model_eval.png` 和 `04_feature_importance.png` 在构建时裁成 5 张单面板，所以页面里看到的静态图数量会更多。

没有放进主视图的 6 张：

| 图 | 为什么没放 |
|---|---|
| `02_k_selection.png` | k 选择过程图，属于方法中间产物；原图右侧注释与柱子有重叠，缩小后更不可读 |
| `02_value_scatter.png` | 1.7 万个点的价值散点；和 3×4 人群矩阵讲同一件事，缩小后点过密 |
| `02_segment_matrix.png` | 和上方的交互矩阵重复；人数、占比、完成率已并入矩阵每个格子 |
| `03_offer_matrix.png` | 已由 02 的交互选择表 + 两张 ECharts 热力图覆盖 |
| `03_budget_compare.png` | 已由 03 的交互预算图和 S0/S1/v2 对比覆盖；原图还是旧高饱和配色 |
| `04_segment_response.png` | 已由 04 的分人群校准表 + 校准曲线覆盖；原图是旧橙蓝配色 |

如果课程/答辩硬性要求“全部原图都要出现”，可以单独做一页附录，但不建议塞进主视图；那会把 02、03、04 变成同一结论的两三套重复图。
